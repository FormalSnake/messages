# Rust parity checklist

Every user-visible feature and behaviour of the TypeScript client, with the
TS source it comes from. Paths are relative to `packages/core/src/` for core
items and `apps/desktop/src/ui/` for UI items unless written in full. Tick an
item only when the Rust build does it on Linux and macOS.

## Core

### Connection and reconnect
- [ ] Connect retries forever with backoff 2 s doubling to 30 s until the server answers; only `stop` gives up (store.ts:127-128, 434-448)
- [ ] `connection_error` holds why the last attempt failed while not online; cleared on success (store.ts:439-442, 583)
- [ ] Waiting sleeps are cut short by `stop` and by a reconnect (store.ts:451-461, 585)
- [ ] Transition to online after being offline: wake sleepers, reconcile if chats exist, flush the outbox, sync prefs (store.ts:581-590)
- [ ] `connect` fetches `/server/info` first, emits `Server`, then contacts; with a seeded contact index the socket opens without waiting for contacts (bluebubbles/client.ts:153-177)
- [ ] Opening a new socket closes the previous one so a retry never leaves two reconnecting (bluebubbles/client.ts:623-625)
- [ ] Socket options: websocket transport only, `password` as a query parameter (bluebubbles/client.ts:627-630)
- [ ] Socket auto-reconnects like socket.io-client (1 s to 5 s, jitter, forever) and every `connect` refetches `/server/info` (bluebubbles/client.ts:634-646)
- [ ] `connect_error` and `disconnect` emit Offline with the reason (bluebubbles/client.ts:648-658)
- [ ] Capabilities recomputed from every `Server` event (store.ts:592-594; model.ts:204-225)
- [ ] REST: `/api/v1<path>?password=`, 30 s timeout, 5 min for uploads and downloads (bluebubbles/client.ts:735-767)
- [ ] Envelope unwrap: `encrypted: true` fails with "Turn off \"Encrypt communications\" in the BlueBubbles server settings"; status >= 400 fails with the server's message (bluebubbles/client.ts:777-788)
- [ ] Send method is `private-api` when private API and helper are both on, else `apple-script` (bluebubbles/client.ts:501-503)

## Better than TS

- [ ] Linux client-side decorations with drag, double-click maximize and window controls via gpui-kit `TitleBar::window_options()`
- [ ] App id `es.canarycoders.messages`, shipped `es.canarycoders.messages.desktop` and icon, so Hyprland rules and GNOME's dock group and show it
- [ ] Per-view invalidation: a `StoreEvent` notifies only the entities watching it (sidebar row, bubble, header, composer) instead of re-rendering the whole tree
- [x] GIFs decoded once per shared file and stepped by a clock that notifies only the bubbles showing it, with no React rebuild per frame and no ffmpeg frame dump
- [ ] Stills (previews, tiles, tail cuts, avatars) derived in process with the `image` crate; ffmpeg only for video posters and HEIF
- [ ] Drag files onto the window to attach them (TS has no drop target)
- [ ] No system TLS: rustls everywhere, so the Linux build needs no OpenSSL
- [ ] Performance budget from `docs/rust-architecture.md` met and measured: cold start under 150 ms, chat switch and keystroke under one frame, idle CPU about 0%
